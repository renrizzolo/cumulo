# @cumulo/css

A type-safe CSS framework with zero external runtime dependencies.

### Runtime dependencies and execution

Understand where `@cumulo/css` runs and what dependencies it requires:

- **Zero production dependencies**: `@cumulo/css` has no external dependencies in `package.json`. It adds no third-party libraries to your client bundle.
- **Build-time dependency**: Install `@cumulo/unplugin` as a development dependency (`devDependencies`). At build time, the plugin extracts CSS rules from `style()`, `create()`, and `keyframes()` into static `.css` files.
- **Zero runtime CSS injection**: In production, the client bundle contains no CSS parser and injects no `<style>` tags into the document head.
- **Runtime JavaScript execution**:
  - `recipe()` returns a function that computes pre-compiled class names based on variant options.
  - `cx()` concatenates and filters class name strings.
  - `props()` returns `{ className, style }` objects for JSX element spreading.

### Installation

Install `@cumulo/css`:

```bash
pnpm add @cumulo/css
```

To extract static CSS at build time, install `@cumulo/unplugin` as a development dependency.

```bash
pnpm add -D @cumulo/unplugin
```

Configure the plugin in your bundler:

##### Vite

```ts
// vite.config.ts
import { defineConfig } from 'vite';
import { cumulo } from '@cumulo/unplugin/vite';

export default defineConfig({
  plugins: [cumulo()],
});
```

##### Webpack

```ts
// webpack.config.js
const { cumulo } = require('@cumulo/unplugin/webpack');

module.exports = {
  plugins: [
    cumulo({
      include: ['./src/**/*.{ts,tsx}'],
    }),
  ],
};
```

For Next.js, Rollup, esbuild, and Parcel configurations, see the dedicated [Bundler Setup guide](/bundlers).

### Style rules

Use `style()` to define scoped, atomic class names. Use `create()` to define multiple rules in one object.

Design tokens imported from `vars` reference CSS variables provided by `@cumulo/core/theme.css`. Import `@cumulo/core/theme.css` at your application root to supply these CSS variables and reset styles, or provide your own stylesheet defining the variables.

```tsx
import { style, create } from '@cumulo/css';
import { vars } from '@cumulo/core';

// Single style definition
export const card = style({
  padding: vars.spacing.lg,
  backgroundColor: vars.bg['0'],
  borderRadius: vars.radius.md,
  border: `1px solid ${vars.border}`,
  boxShadow: vars.shadow['1'],
  ':hover': {
    boxShadow: vars.shadow['2'],
  },
  '@media': {
    '(max-width: 640px)': {
      padding: vars.spacing.sm,
    },
  },
});

// Multi-rule definition
export const buttonStyles = create({
  base: {
    display: 'inline-flex',
    alignItems: 'center',
    justifyContent: 'center',
    borderRadius: vars.radius.md,
    fontWeight: 600,
  },
  primary: {
    backgroundColor: vars.primary.DEFAULT,
    color: vars.primary.fg,
  },
  outline: {
    border: `1px solid ${vars.border}`,
    backgroundColor: 'transparent',
  },
});
```

At build time, the extractor replaces each rule with a hashed class name and outputs static CSS.

### Recipes

Use `recipe()` to define multi-variant styles with default variants and compound variants.

`recipe()` compiles variant CSS rules ahead of time. At runtime, the returned function joins the matching class names:

```tsx
import { recipe, type RecipeVariants } from '@cumulo/css';
import { vars } from '@cumulo/core';

export const button = recipe({
  base: {
    display: 'inline-flex',
    alignItems: 'center',
    justifyContent: 'center',
    fontWeight: 500,
    borderRadius: vars.radius.md,
  },
  variants: {
    variant: {
      primary: { backgroundColor: vars.primary.DEFAULT, color: vars.primary.fg },
      secondary: { backgroundColor: vars.bg['1'], color: vars.fg },
      outline: { backgroundColor: 'transparent', borderColor: vars.border },
    },
    size: {
      sm: { height: vars.size.sm, padding: '0 12px' },
      md: { height: vars.size.md, padding: '0 16px' },
    },
  },
  compoundVariants: [
    {
      variants: { variant: 'outline', size: 'sm' },
      style: { borderWidth: 1 },
    },
  ],
  defaultVariants: {
    variant: 'primary',
    size: 'md',
  },
});

export type ButtonVariants = RecipeVariants<typeof button>;

// Call the recipe function at runtime:
const className = button({ variant: 'secondary', size: 'sm' });
```

### Theme contracts

Use `createThemeContract()` to create type-safe CSS custom properties without values.

Implement themes with `createTheme()`, or override contract variables inside recipes using `.$set()`:

```tsx
import { createThemeContract, createTheme, recipe } from '@cumulo/css';

// 1. Define the contract
export const colorContract = createThemeContract(
  {
    brand: null,
    surface: null,
  },
  'color',
);

// 2. Create themes matching the contract
export const lightTheme = createTheme(colorContract, {
  brand: '#2563eb',
  surface: '#ffffff',
});

export const darkTheme = createTheme(colorContract, {
  brand: '#3b82f6',
  surface: '#0f172a',
});

// 3. Override contract variables inside recipes or style rules
export const cardRecipe = recipe({
  base: {
    backgroundColor: colorContract.surface,
  },
  variants: {
    highlight: {
      true: {
        ...colorContract.$set({
          surface: '#f1f5f9',
        }),
      },
    },
  },
});
```

Themes generate scoped class names and inject no client-side runtime styles when compiled with `@cumulo/unplugin`.

### Keyframe animations

Use `keyframes()` to define scoped CSS animation keyframes:

```tsx
import { keyframes, style } from '@cumulo/css';

export const spin = keyframes({
  from: { transform: 'rotate(0deg)' },
  to: { transform: 'rotate(360deg)' },
});

export const spinner = style({
  animation: `${spin} 1s linear infinite`,
});
```

### Class merging and JSX props

Use `cx()` to merge class names, conditional values, and compiled styles.

Use `props()` to merge class names and inline styles into an object for JSX spreading:

```tsx
import { cx, props } from '@cumulo/css';
import { buttonStyles } from './button.js';

// Merge class names:
const className = cx(buttonStyles.base, isPrimary && buttonStyles.primary, 'custom-class');

// Return { className, style } for JSX spreading:
const elementProps = props(buttonStyles.base, { style: { marginTop: 8 } });

<button {...elementProps}>Save</button>;
```

Both `cx()` and `props()` run in JavaScript at runtime. They perform string concatenation and object assignment without DOM side effects.
