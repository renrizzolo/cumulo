# Bundler Integration

<BundlerAlert />

### Why a bundler integration is required

Traditional CSS-in-JS libraries inject runtime `<style>` tags into the DOM during browser execution. Cumulo rejects this approach for performance, security, and React Server Components (RSC) compatibility:

- **Zero-runtime client overhead**: Production bundles contain no CSS parser, no runtime style injector, and zero CSS AST overhead.
- **Pure static CSS output**: Styles written with `style()`, `recipe()`, and design tokens from `@cumulo/core` compile into standard `.css` files managed by your bundler.
- **Full React 19 & RSC support**: Because no runtime DOM mutations occur during style resolution, Cumulo runs seamlessly across Server Components, SSR, static generation, and client islands.

To make this possible, `@cumulo/unplugin` (or `@cumulo/parcel-transformer`) intercepts your modules at build time, evaluates style declarations in isolated contexts, and attaches extracted styles directly to your bundler's asset graph.

### Installation

Install the build plugin as a development dependency:

```bash
# For Vite, Webpack, Next.js, Rollup, or esbuild:
pnpm add -D @cumulo/unplugin

# For Parcel:
pnpm add -D @cumulo/parcel-transformer
```

### Bundler configurations

#### Vite

Import `cumulo` from `@cumulo/unplugin/vite` and register it in `plugins`:

```ts
// vite.config.ts
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';
import { cumulo } from '@cumulo/unplugin/vite';

export default defineConfig({
  plugins: [react(), cumulo()],
});
```

Load the theme stylesheet at your application root:

```ts
// src/main.tsx
import '@cumulo/core/theme.css';
```

`@cumulo/core/theme.css` provides the CSS reset and theme variables. If you maintain a custom stylesheet defining the variables, import your custom file instead.

#### Next.js

Cumulo supports Next.js with both **Turbopack** (the default engine in Next.js 16+) and **Webpack**, across App Router and Pages Router.

##### Option A: PostCSS (Recommended for Turbopack & Webpack)

Because Turbopack processes CSS via PostCSS rather than Webpack plugins, use `@cumulo/unplugin/postcss`. This requires **zero** changes to `next.config.mjs` and works identically under Turbopack and Webpack.

1. **Add the PostCSS plugin** in `postcss.config.mjs`:

```js
// postcss.config.mjs
export default {
  plugins: {
    '@cumulo/unplugin/postcss': {},
  },
};
```

2. **Import `@cumulo/core/theme.css` and add `@cumulo;`** to your global stylesheet (`app/globals.css` for App Router, or `styles/globals.css` for Pages Router):

```css
/* app/globals.css or styles/globals.css */
@import '@cumulo/core/theme.css';
@cumulo;
```

`@cumulo/core/theme.css` provides the CSS reset and default theme variables. `@cumulo;` marks where PostCSS injects the extracted component styles. If you maintain a custom stylesheet with your own CSS variables, import your custom stylesheet instead of `@cumulo/core/theme.css`.

##### Option B: Webpack via `withCumulo`

If you are using Next.js with Webpack (`next build --webpack` or Next.js 14/15) and prefer not to use PostCSS, wrap your `next.config.mjs` with `withCumulo` from `@cumulo/unplugin/next`:

```js
// next.config.mjs
import { withCumulo } from '@cumulo/unplugin/next';

/** @type {import('next').NextConfig} */
const nextConfig = {
  // Your Next.js config options
};

export default withCumulo(nextConfig);
```

#### Webpack

Import `cumulo` from `@cumulo/unplugin/webpack`. Pair it with `mini-css-extract-plugin` and `css-loader`:

```js
// webpack.config.js
const { cumulo } = require('@cumulo/unplugin/webpack');
const MiniCssExtractPlugin = require('mini-css-extract-plugin');

module.exports = {
  module: {
    rules: [
      {
        test: /\.css$/,
        use: [MiniCssExtractPlugin.loader, 'css-loader'],
      },
    ],
  },
  plugins: [
    cumulo(),
    new MiniCssExtractPlugin({
      filename: '[name].css',
    }),
  ],
};
```

#### Rollup

Import `cumulo` from `@cumulo/unplugin/rollup`:

```js
// rollup.config.js
import { cumulo } from '@cumulo/unplugin/rollup';

export default {
  plugins: [cumulo()],
};
```

#### esbuild

Import `cumulo` from `@cumulo/unplugin/esbuild`:

```js
// build.js
import * as esbuild from 'esbuild';
import { cumulo } from '@cumulo/unplugin/esbuild';

await esbuild.build({
  entryPoints: ['src/index.tsx'],
  bundle: true,
  outdir: 'dist',
  plugins: [cumulo()],
});
```

#### Parcel

Parcel uses a dedicated transformer plugin `@cumulo/parcel-transformer`. Register it in your `.parcelrc`:

```json
// .parcelrc
{
  "extends": "@parcel/config-default",
  "transformers": {
    "*.{ts,tsx,js,jsx}": ["@cumulo/parcel-transformer", "..."]
  }
}
```

### How static extraction works

{/* prettier-ignore */}
<CodeBlock lang="txt" withCopy={false}>
 {`Component / Style File
       │
       ▼
  [@cumulo/unplugin Hook]
       │
       ├─► Evaluates module via isolated Jiti context
       ├─► Collects compiled CSS rules from @cumulo/css
       │
       ▼
Virtual Module (.cumulo.css)
       │
       ▼
Host Bundler CSS Pipeline ──► Emits static styles.css`}
</CodeBlock>

1. **File Scanning**: The plugin monitors source files and `@cumulo/*` packages in `node_modules` for calls to `style()`, `create()`, `recipe()`, `keyframes()`, and theme contracts.
2. **Evaluation**: Matches are evaluated via an isolated Node runtime loader (`jiti`), executing the style functions and capturing CSS in the internal stylesheet registry.
3. **Virtual CSS Injection**: The plugin injects an import to a virtual stylesheet (e.g. `App.tsx.cumulo.css`) at the top of the module.
4. **Bundler Hand-off**: The host bundler (Vite, Webpack, etc.) treats the virtual module as standard CSS, applying PostCSS, autoprefixing, minification, and code splitting.

### Plugin options

The `cumulo()` plugin factory accepts an optional configuration object:

```ts
cumulo({
  include: ['./src/**/*.{ts,tsx}'],
  exclude: ['**/*.stories.{ts,tsx}'],
});
```
